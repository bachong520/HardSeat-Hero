#### 同价舒适性排序

- 搜索主排序仍保持严格最低价优先。
- 新增 `_plan_sort_key()`，排序顺序调整为：
  1. `total_price`
  2. 中途等待时间舒适性惩罚
  3. 换乘次数
  4. 总耗时
- 新增 `_transfer_wait_comfort_penalty()`：
  - 换乘等待 `30~120` 分钟视为舒适，惩罚为 `0`。
  - 等待小于 `30` 分钟视为过短，按风险加重惩罚。
  - 等待超过 `120` 分钟视为过长，按超出分钟数惩罚。
- 该评分只影响同价方案排序，不改变合法性过滤，也不改变最低价主目标。

#### 同价方案保留

- 价格剪枝边界从 `>= best_price` 调整为 `> best_price`。
- 一换搜索和多次中转搜索都允许保留同价候选，避免同价舒适性排序没有候选可排。

#### 方案去重

- 新增 `_deduplicate_plans()` 和 `_plan_identity_key()`。
- 按车次号、起终站、出发时间和到达时间组成方案身份，去除重复方案。

## 2026-06-27 S05 后端数据源异常模型与 HTTP 映射统一

### 目标

不同 `TrainDataProvider` 的可预期失败都应返回一致状态和结构，API 层不应只识别 `Railway12306Error`。

### 已完成成果

#### 异常模型

- 更新 `backend/app/adapters/base.py`。
- 保留 `TrainDataProviderError` 作为所有 provider 可预期异常的基类。
- 新增细分异常类型：
  - `TrainDataUnavailableError`
  - `TrainDataConfigurationError`
  - `TrainDataBadRequestError`

当前语义：

- `TrainDataProviderError`：默认数据源失败，映射为 `502`。
- `TrainDataBadRequestError`：provider 层识别出的请求类问题，映射为 `400`。
- `TrainDataConfigurationError`：provider 配置不可用，映射为 `503`。
- `Railway12306Error` 仍继承 `TrainDataProviderError`，因此现有 12306 错误行为保持兼容。

#### API 映射

- 更新 `backend/app/api/routes.py`。
- `POST /api/routes/search` 不再只捕获 `Railway12306Error`，改为统一捕获 `TrainDataProviderError`。
- 新增 `provider_error_status_code()`，集中维护 provider 异常到 HTTP 状态码的映射。
- `POST /api/routes/search/stream` 也改为捕获 `TrainDataProviderError`。
- 流式接口仍沿用当前 NDJSON `{ "error": "..." }` 行格式，没有在本切片改变协议。流式事件协议留给 S06。

#### 测试覆盖

- 更新 `backend/tests/test_api.py`。
- 新增 `FailingProvider`，模拟普通 provider 抛出 `TrainDataProviderError`。
- 新增测试：
  - `test_route_search_maps_provider_error_to_bad_gateway`
  - `test_stream_route_emits_provider_error`

测试覆盖点：

- 普通 JSON 查询接口对 provider 基类异常返回 `502`。
- 流式接口对 provider 基类异常输出 `{ "error": "数据源失败" }`。
- 避免回退到只捕获 `Railway12306Error` 的旧行为。
